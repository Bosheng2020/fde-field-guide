# Forward Deployed Engineer 能力矩阵

**语言：** [English](../en/04-skills-matrix.md) · 简体中文  
**内容类型：** 作者总结与自评量表  
**最后检查：** 2026-10-22

优秀的 FDE 通常呈 T 型：能力广度足以负责完整链路，同时在与产品和客户最相关的一个或多个领域具有深度。

## 熟练度等级

- **L1 — 理解：** 能解释概念，并在指导下参与；
- **L2 — 交付：** 能独立完成边界清晰的生产任务；
- **L3 — 领导：** 能跨团队设计并负责一个模糊部署；
- **L4 — 放大：** 能建立系统、标准和培养机制，提升整个组织。

## 能力矩阵

| 领域 | L1 证据 | L2 证据 | L3 证据 | L4 证据 |
|---|---|---|---|---|
| 需求发现与范围 | 梳理工作流 | 定义最小切片和指标 | 把模糊需求重新谈成结果约定 | 建立可复用的筛选/定义系统 |
| 端到端工程 | 参与一个技术层 | 发布完整的小型服务/流程 | 负责多系统生产架构 | 建立可复用的平台能力 |
| AI / LLM 系统 | 正确使用模型和工具 | 构建带知识或工具的工作流 | 诊断系统与模型失败并取舍 | 用一线证据影响模型/产品路线图 |
| 评估 | 编写测试案例 | 建立任务评估和 Trace | 将回归与风险、商业结果连接 | 建立组织级评估体系 |
| 可靠性与安全 | 遵循控制要求 | 实现权限、监控和降级 | 按风险主持生产就绪评审 | 定义可扩展治理和事故模式 |
| 产品判断 | 理解用户需要 | 优先高价值窄场景 | 平衡客户特例与产品杠杆 | 跨客户识别类别级模式 |
| 客户沟通 | 解释技术工作 | 主持工作会和困难进度沟通 | 协调管理层、用户、工程和风险团队 | 建立可信交付文化并培养负责人 |
| 采用与价值 | 追踪使用量 | 设计推广并衡量结果 | 重构流程/激励以维持采用 | 建立可复用的扩展与价值系统 |
| 项目执行 | 管理个人任务 | 安排边界清晰的项目 | 在压力下管理多项依赖 | 改进项目组合的人力和交付体系 |
| 一线到产品 | 汇报故事 | 提交可重复问题 | 产出评估、组件和产品方案 | 建立可复利的学习闭环 |

## 技术广度清单

AI 方向 FDE 应能理解并讨论：

- Python 和/或 TypeScript、API、Schema、数据库和队列；
- 前端工作流与用户交互；
- 数据接入、检索、索引和血缘；
- 模型选择、Prompt、上下文、结构化输出、工具调用和 Agent；
- 评估集、Grader、Trace、实验和回归测试；
- 云、容器、CI/CD、Secrets、网络、监控和成本；
- 认证、授权、多租户、隐私、审计和保留策略；
- 人工审批、升级、回滚和事故响应。

它不是关键词清单。真正的证据是你曾构建、调试或运营完整链路。

## 能够放大技术能力的“非技术能力”

- 听出功能请求背后的真实决策；
- 写清问题、取舍和决策记录；
- 尽早传递坏消息，同时保持信任；
- 跨文化、跨技术深度沟通；
- 在事故和管理层压力下保持冷静；
- 区分紧急与重要；
- 知道何时停止、简化或使用确定性软件。

## 作品集应该提供什么证据

一个可信项目应展示：

1. 真实或认真模拟的工作流；
2. 基线和明确成功标准；
3. 端到端架构与运营限制；
4. 代表性评估，而不是精选 Prompt；
5. 安全和人工控制决策；
6. 生产部署和监控；
7. 失败分析与迭代；
8. 可衡量结果，或诚实解释为什么项目被停止。

仓库本身不如它公开了哪些证据和决策重要。

## 自我评估方法

为每个领域写下一项能够证明你所声称等级的产物或案例。如果无法指出证据，把自评降低一级，并设计一个能够产生证据的项目。
