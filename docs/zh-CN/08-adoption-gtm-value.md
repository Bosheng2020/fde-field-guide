# Forward Deployment 中的 AI 采用、GTM 与可衡量价值

**语言：** [English](../en/08-adoption-gtm-value.md) · 简体中文  
**内容类型：** 客户交付与商业化实战手册  
**最后检查：** 2026-10-22

有用系统只有成为日常工作，生产部署才算完成。用户采用不是上线后的宣传任务，而是产品、工作流、激励和信任问题。

## 梳理利益相关者系统

| 相关方 | 他们需要什么 | 忽略后的常见失败 |
|---|---|---|
| 高管发起人 | 战略结果、风险可见性、可信里程碑 | 项目失去支持，或紧迫性变得随意 |
| 工作流负责人 | 控制、责任和运营适配 | 改变后的流程无人负责 |
| 一线用户 | 更低摩擦、明确收益、安全修正 | 绕过系统或放弃使用 |
| 领域专家 | 专业准确、可解释、审核权 | 不信任或不安全验收标准 |
| 工程 / 平台团队 | 可维护性、接口和支持边界 | 集成债务与运营冲突 |
| 安全 / 法务 / GRC | 数据、控制、审计与风险证据 | 最后阶段阻止上线 |
| 产品 / 研究 | 可重复模式和有优先级的证据 | 一线学习停留在故事层面 |
| 商务负责人 | 价值叙事、范围和扩展信号 | 过度承诺、错误定价或误判成功 |

## 从工作流经济性开始

建立基线，例如：

- 每个案例处理时间和队列等待；
- 每项完成任务的成本；
- 错误、返工或升级率；
- 收入 / 转化或避免的损失；
- 释放的专家产能；
- 合规或风险暴露；
- 用户体验和响应时间。

同时衡量部署总成本：模型和基础设施、集成与支持时间、人工审核、培训、治理和预计事故成本。ROI 是决策模型，不是营销百分比。

## 采用漏斗

```mermaid
flowchart LR
    A[符合条件的用户] --> B[激活]
    B --> C[第一次成功完成工作流]
    C --> D[重复使用]
    D --> E[工作流依赖]
    E --> F[扩展 / 推荐]
```

追踪用户在哪一步流失，并直接访谈。重复使用低可能是质量问题，也可能来自权限缺失、时机错误、多余审批、管理者激励或工作本身低频。

## 信任应该被正确校准

目标不是最大化信任。用户应知道：

- 系统设计用来做什么；
- 哪些证据支持答案；
- 系统无法知道什么；
- 何时必须审核；
- 如何修正、覆盖和升级；
- 他们的数据和反馈会如何处理。

过度信任和采用不足同样危险。

## 上线方法

1. 招募能够代表真实用户的内部推动者，而不只是 AI 爱好者；
2. 围绕真实工作流和失败模式培训；
3. 从小范围用户开始，并提供清晰支持渠道；
4. 高频复盘 Trace、修正和摩擦；
5. 公开哪些改动来自用户反馈；
6. 把用户、场景和自主范围分别逐步扩大；
7. 明确新的运营负责人。

## FDE 也是 GTM 的一部分

FDE 不一定属于销售，但优秀一线工作会塑造 Go-to-Market：

- 发现哪些用例具有紧迫且可重复的价值；
- 产出由结果支持的参考架构和证明；
- 区分产品缺口与使用/赋能缺口；
- 影响包装、实施成本和现实时间表；
- 识别扩展路径和应该拒绝的条件；
- 为管理层和实践者创造可信语言。

反馈必须保持真实。战略客户身份不会让薄弱证据自动变强。

## 从一线请求到产品信号

把客户请求转化为结构化信息：

- 工作流和受影响用户；
- 频率和严重度；
- 可重复 Trace 或产物；
- 当前临时方案及影响；
- 是否在多个客户重复出现；
- 可复用产品能力，而不仅是被请求的功能；
- 修改确实改善结果的证据。

可直接使用[一线信号模板](../../templates/field-signal.zh-CN.md)。

## 跨地区和现场工作

许多 FDE 岗位需要大量出差，但比例取决于具体公司和职位。有效现场工作需要文化好奇心、理解当地决策方式、清晰书面跟进，并避免知识只保留在出差人员脑中。

现场工作前明确需要完成的决策、访问、用户和产物；结束后发布决策日志、负责人、证据、风险和下一步。出差应该缩短反馈周期，而不是替代项目结构。

## 扩展门槛

只有满足以下条件才扩大：

- 原工作流已有稳定负责人；
- 重复使用和任务质量能够持续；
- 商业价值高于完整运营成本；
- 安全和支持能力能够随范围扩展；
- 已理解下一批用户的差异；
- 核心模式确实可复用，而不是盲目复制。

否则应继续改进、重构或停止。
