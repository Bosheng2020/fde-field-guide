# 挑战与反模式

**语言：** [English](../en/09-challenges-antipatterns.md) · 简体中文  
**内容类型：** 诊断指南  
**最后检查：** 2026-10-22

最昂贵的 FDE 失败，往往在最初几周看起来很像进展。以下模式用于尽早诊断。

## 1. 按请求构建方案，却没有找到问题

**信号：** 项目从“给我们做一个 Agent”开始，却没有基线、用户决策或失败边界。  
**为什么失败：** 被指定的技术可能没有解决真正限制业务的因素。  
**应对：** 观察最近真实案例、梳理工作流，在扩大范围前写出结果约定。

## 2. Demo 表演

**信号：** 成功依赖精选 Prompt、隐藏人工步骤、广泛管理员权限，或每次都由 FDE 亲自操作。  
**为什么失败：** 把“可能做到”误认为“可重复、可运营”。  
**应对：** 使用代表性案例、真实身份、故障依赖和普通用户测试，并公开人工介入。

## 3. 万能 Agent

**信号：** 一个 Agent 拥有大量宽泛工具、状态不清、Prompt 巨大，并跨多个无关流程拥有权限。  
**为什么失败：** 评估、权限、恢复和责任都变得不可管理。  
**应对：** 缩窄工作流，分开确定性与模型决策，使用强类型工具并拆分权限。

## 4. 一开始就做微调

**信号：** 还没有区分系统性错误与上下文缺失、检索差、工具含糊、编排弱或不可能要求。  
**为什么失败：** 训练会编码噪声，却没有修复系统缺陷。  
**应对：** 先修正任务定义和系统层；只有在模式稳定、数据高质量并有保留评估时才后训练。

## 5. 把客户分叉当作产品战略

**信号：** 每次部署都复制代码库并加入永久条件分支。  
**为什么失败：** 修复、安全控制和产品改进无法安全传播。  
**应对：** 维护可复用核心、受支持配置层和明确客户边缘；每个特例都决定上游、本地维护或下线。

## 6. 过早抽象平台

**信号：** 团队还没有端到端解决一个工作流，就设计通用框架。  
**为什么失败：** 抽象基于想象的共性，而不是观察到的重复。  
**应对：** 先完整解决具体问题，对比多个实例后再提取稳定能力。

## 7. 通过隐藏风险来追求速度

**信号：** 安全、评估、回滚或负责人被推迟，却没有明确决策。  
**为什么失败：** 上线变成第一次真实测试。  
**应对：** 通过缩小范围和自主权来加速；记录已接受风险、负责人、到期时间和缓解措施。

## 8. 有指标，没有决策

**信号：** 仪表盘越来越多，但没人知道哪个阈值会改变上线、模型或范围。  
**为什么失败：** 可观测性变成装饰。  
**应对：** 每个关键指标都绑定负责人、决策、阈值和复盘节奏。

## 9. 把采用只当作培训问题

**信号：** 使用量低时，只增加文档或培训。  
**为什么失败：** 工作流可能增加摩擦、威胁激励、出现时机不对，或缺少管理者支持。  
**应对：** 观察流失点，重构工作流和激励，并让收益体现在用户的工作单位中。

## 10. 英雄式 FDE

**信号：** 架构、客户信任、凭据、运行手册和事故知识都集中在一个人。  
**为什么失败：** 该人员缺席或移交时，部署无法生存。  
**应对：** 结对、记录决策、轮换支持、测试移交，并在上线前指定长期负责人。

## 11. 战略客户例外主义

**信号：** 大客户长期绕过产品、安全或证据标准。  
**为什么失败：** 收入压力创造无限维护成本和声誉风险。  
**应对：** 所有例外都必须限时，并有审批人、成本、学习目标和退出条件。

## 12. 把一线反馈停留在故事

**信号：** 路线图请求只说“客户想要”，却没有频率、Trace、影响或复现情况。  
**为什么失败：** 产品和研究团队无法比较或重现问题。  
**应对：** 把观察转化为脱敏 Trace、评估案例、严重度/频率估计和经过测试的干预。

## 部署就绪矩阵

每个维度按 **0 未知、1 假设、2 试点证据、3 生产验证**评分。

| 维度 | 0–3 分 | 所需证据 |
|---|---:|---|
| 商业价值 |  | 基线、结果指标、经济负责人 |
| 工作流清晰度 |  | 观察案例、例外、范围 |
| 数据与集成访问 |  | 真实访问、权限、质量 |
| 可靠性与评估 |  | 代表性评估、Trace、回归 |
| 安全与治理 |  | 威胁模型、控制、审批人 |
| 采用与运营 |  | 用户、负责人、支持、上线证据 |

建议门槛（并非统一标准）：

- **探索：** 未知项已明确，并有安全学习方法；
- **试点：** 不存在完全未知的维度；
- **生产：** 可靠性/评估和安全/治理至少有试点证据；
- **扩展：** 采用/运营已在生产验证，并存在回归证据。

分数应该触发决策和工作计划，而不是成为炫耀的总分。
