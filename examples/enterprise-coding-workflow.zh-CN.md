# 教学案例：企业 AI 编码工作流部署

**语言：** [English](enterprise-coding-workflow.md) · 简体中文  
**类型：** 虚构教学案例，不代表真实客户

## 最初请求

一家企业的工程负责人希望在一个季度内“给所有开发者上线 AI Coding Agent”。

## Frame

访谈和代码仓库分析显示实际存在三个不同需求：理解不熟悉的服务、迁移即将弃用的内部 API，以及减少重复修改的评审时间。广泛分发许可证无法证明任何一个结果。

第一次结果改为：**在不增加线上缺陷和审核负担的前提下，减少一组服务完成某项重复 API 迁移的时间。**

## Instrument

评估集包含已完成的历史迁移、代表性仓库、权限边界、失败测试、生成 Diff 的人工评审，以及正确行为是不修改代码的案例。指标包括任务完成、Diff 接受率、缺陷、审核时间、CI 通过、延迟、成本和开发者重复使用。

## Engineer

- 只索引每位开发者有权访问的仓库；
- 首先以只读方式提供迁移指南和代码搜索工具；
- 在隔离分支或沙箱执行修改；
- 合并前必须通过测试、静态检查和人工审核；
- 记录模型/工具版本，让每项修改建议可追踪到证据；
- 部署凭据不得交给编码 Agent。

## Launch

选择真正计划开展迁移、且服务具有代表性的团队试点。培训开发者如何审核生成修改、反馈失败和保护 Secret。除了被接受的 Diff，也要复盘被拒绝的内容，理解系统在哪些地方浪费注意力。

## Distill

把重复修复提炼为仓库指令、迁移专用工具、评估案例、CI 规则和产品反馈。只有第一个工作流形成稳定采用和运营责任后，才扩展到其他流程。

## 核心经验

成功不是“开通了多少账号”或“生成了多少行代码”，而是有证据的工作流结果、可持续使用、安全工程行为和可复用经验。
